# 路线版本与地图初始位置修复验收

2026-10-07。本次针对完整录像上传轨迹与 Web 底图叠加；不改变 120 秒片段或原录制姿态频率。

## 原因与修复

本机安装为 PEAK 2.6.b / Steam build **25739797**；修复前网站的 21 张底图全部来自 2.4.c / **25306743**。21 个同名场景的源文件 SHA 全部变化。例如旧 Level_17 的第二关为 Roots，新 Level_17 为 Tropics，不能仅修改版本号后套用旧模型。

从本机新版本原生 UnityFS 数据只读解包，按 BuildSettings 的真实场景表重新导出全部 21 张地图。原三角网格、完整父链 TRS、静态批次和厘米坐标保持；256×256 PNG/高度场只用于平面参考。旧 21 张地图保留，各自按精确 build/scene/分支选择。地图、原版路线、雾、水面、城塞外壳、顶峰边界和地标旁数据逐图绑定源场景 SHA。

Mod v0.8.1 在地图就绪时一次记录关卡根的世界 TRS 与原版进度点 XYZ，白名单上传 `map.alignment`。服务器用同版本源地标拟合整体正向刚性变换，要求至少三个分散、不共线点、所有残差 ≤5 cm、每个根的旋转与缩放吻合。不同版本、错误关卡、非刚性变化和缺少证据不能借用底图。路线与热力使用同一已核验变换；私人原始坐标、10 Hz 时间点与断点保持。

没有三维地标的旧录像，仅在原布局哈希、同源 DLL MVID、根路径/XYZ、原生门限及“运行时不写根 TRS”的源证明完全一致时验证原位；不能猜测偏移或补造地标。缺少这类信息的早期录像仍可投稿，但不足以可靠叠加。
