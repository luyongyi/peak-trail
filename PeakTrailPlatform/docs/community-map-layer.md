# 地图内大家的线路与热力

这项功能直接位于首页「进入地图」后的现有 3D 地图，保留同一套原版场景模型与相机。
首页不再提供独立路线收集入口。地图默认铺满视图，路线侧栏和图层均收起，实时追踪入口、演示和轮询默认隐藏。

## 使用

1. 在首页选择关卡并点击「进入地图」。
2. 点击顶部「返回」旁的「路线与热力」，展开侧栏，再用「线路图层」选择「大家的路线」或「热力图」。再次点击该按钮会收起侧栏并关闭图层。
3. 在侧栏按难度、高度层筛选；路线模式可勾选个人路径，同名玩家仍各自独立。
4. 多个录制布局组分别选择，不自动合并。选择「所有关概览」时收起本关线路，需要选具体关卡再看统计。
5. 返回首页或切到本地日志回放时，取消未完成的路线请求并移除社区图层；个人日志不会自动上传。

数据来自独立 Peak Memories Mod 完整录像库的主动「上传轨迹」。本地先提取最多 10 Hz 的
角色坐标、姓名与必要地图/状态信息，预览并确认后发送精简包；不上传原始录像，也不适配
120 秒回忆片段。上传默认待审核，每位玩家完整通过当前关卡的有效尝试才进入公开统计。
地雷、物品、角色外观和高频骨骼数据不进入路线包。

## 地图和显示约束

路线只能叠到确切匹配的 `mapPackId`、游戏构建、实际场景、原生关卡顺序和终章分支上。
相同 `Level_N`、今天的日期或一个相同关卡名都不能证明版本与布局相同。已有投稿仍是
`waiting-map` 时，保留当前地图并说明没有匹配线路；不借用旧底图，也不伪造热力。

每条完整路线在同一 2 m 空间格只贡献一次，真实高度保留。高度筛选分开山路上下层；
热力以黄到红的透视空间格显示，避免山体和建筑完全遮住路径；侧栏明确标示透视展示。
缺口、传送和记录断点不连接。热力针对选定记录组、关卡和难度下的全部有效路线，
玩家显隐只影响路线图层。单页路线达到数量/点数上限时明确显示截断，不能把当前页
路径数冒充热力总数。

侧栏和图层默认关闭；进入地图时不请求社区数据。展开侧栏才读取小型分组目录，选择路线或热力后才读取具体关卡数据。
同一关的路线、热力与「仅地图」切换复用已加载数据；换关、换难度和主动刷新使缓存失效。
没有定时轮询、SSE、上传调用或新的动画循环。线路图层使用已有场景坐标变换，保持
Unity 原始 XYZ，不贴地、不改变相机，也不替换地图几何。

## 自动验收与边界

客户端控制器的 17 项回归覆盖严格身份/分支、分组隔离、难度/高度/玩家选择、分页提示、
默认零大轨迹请求、缓存、关闭/退出取消以及旧响应不能覆盖新关卡。
地图侧栏的 11 项测试使用真实控制器，仅替换 DOM、HTTP 和 scene 边界，覆盖：

- 首页和回放禁用，进入地图默认纯地图、侧栏关闭且零社区请求；
- 顶部按钮按需展开侧栏，再次点击关闭图层并中断未完成的轨迹请求；
- 换关等待时立即清除旧图层，全山概览不造合计；
- 场景重建后恢复已有选择和缓存，不重新请求；
- 玩家勾选保留记录组、难度、高度及其他玩家显隐；
- 退出后的晚到数据无效，销毁时解绑 UI 事件。
- `[hidden]` 能覆盖侧栏自身的 flex/grid 样式，默认地图模式不会留下空筛选区域。

```powershell
npm --prefix PeakTrailPlatform/web test
npm --prefix PeakTrailPlatform/web run check
node --test PeakTrailPlatform/web/tests/community-routes.test.mjs PeakTrailPlatform/web/tests/community-map-panel.test.mjs PeakTrailPlatform/web/tests/community-route-overlay.test.mjs
```

测试与本地浏览器验收使用合成投稿，不上传真实录像；它们不能证明所有实局数据已经
完整记录，也不能替代游戏 FPS 或正式服务器流量验收。生产上传接口仍需管理员按
[启用说明](../deploy/trajectory-enablement.md) 安装私有持久目录与 service 配置。
