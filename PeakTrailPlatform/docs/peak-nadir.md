# 顶峰与天底：区域、关卡索引与展示规则

核查基准：本机 PEAK 2.4.c / Steam build `25306743` 的游戏程序集及关卡资源。
本说明不是依据日期、地图编号或通关统计推测出的路线。

## 游戏中的真实关系

| 概念 | 游戏 `Segment` 枚举 | `MapHandler.segments` 数组 | 实际含义 |
| --- | --- | --- | --- |
| 熔炉 / 城塞 | `TheKiln = 4` | 4 | 由火山 / 雾沼分支决定的终段 |
| 顶峰 | `Peak = 5` | 同为 4 | 位于终段之上，并非另一张导出地图 |
| 天底 | `Void = 6` | 5 | `VoidBiome` 在运行时追加的额外区域 |

`BiomeType.Peak = 5`、`BiomeType.Void = 17` 又是另一组编号，不能混作数组下标。

- `MapHandler.JumpToSegmentLogic` 对 Peak / Void 的枚举值减一再寻址数组；
  Peak 使用独立的 `respawnThePeak` 位置。
- `VoidBiome` 通过同一场景内的区域切换与传送进入，不是每日四关之一，也不是
  城塞或熔炉之后必定到达的一关。
- 山体进度用空间条件判断顶峰，不能把“当前在数组层 4”直接当作“抵达顶峰”。
- 天底有独立的通关分支与结算横幅。游戏结算修正可能把最后一条统计的 biome
  写为 Peak，即使实际从天底结束；不能用统计最后一项认定登顶。
- 本地 21 份地图包均已有 `segment-05-void` 的 PNG、高度场与 GLB 几何；
  没有单独的顶峰地图层。

主要核查对象：`Segment`、`Biome.BiomeType`、`MapHandler.JumpToSegmentLogic` /
`SetupVoid` / `ForceEnablePeak`、`MountainProgressHandler`、`VoidBiome`、
`CharacterStats.Record` / `FixLastEntry` / `Win`、`Character.RPCEndGame`、`EndScreen`。

## Web 行为

- 保留每日四个主区域与真实的熔炉 / 城塞配对，不把顶峰和天底塞入轮换。
- 首页以“旅程的两种结局”呈现两张独立插画，明确它们是互斥选择而非连续关卡。
  顶峰撤离不会进入天底；进入天底的旅程即使路过顶峰，也不计顶峰结局。
  首页只展示地图可能性，不预判某局的选择。
- build `25306743` 的每个源场景都包含唯一的 `PeakHandler`：熔炉地图对应
  `Volcano_Segment/Peak_Kiln Variant`，城塞地图对应 `Temple_Segment/Peak`，后者还包含
  同级的可碰撞 `Peak Gate`。导出器以组件身份和源场景哈希生成 `mapPeak` 元数据；顶峰入口
  仍复用终段 GLB，但按该子树的非触发碰撞边界取景，并跳过熔炉 / 城塞室内镜头。
  不采用坐标断层或名称包含 `Peak` 的宽泛猜测。其他版本若没有匹配的源场景证据，入口保持禁用。
- 天底入口需要唯一且不矛盾的实际 Void 图层。缺失、身份不匹配、重复或
  冲突的资源不提供可点击入口。过期日图仍只作为历史地图呈现。
- 导航将 Void 命名为“天底”，作为额外区域单独查看；山体概览不混入其大范围
  底面，山体关卡序号也不计入天底。
- 天底默认取景排除已核实版本中约 5 公里的平面水体包围盒，按实际场景主体
  计算镜头距离；水体仍正常渲染，足迹坐标与裁切范围不变。未知版本保持原有
  取景规则，避免误删其他关卡的边界。
- 地图包含某区域不等于录像到过该区域；自动跟随仍服从录像的时间数据。

## 录像便条与封面

封面主题候选应包含顶峰、天底，共 11 种（七个野外区域、两个终段、两个特殊区域）。
现已制作 11 张插画，新增 `peak-v1.png` 与 `nadir-v1.png`，未把雪山插画充作顶峰，
也未把雾沼充作天底。顶峰为鲜花绿草覆盖的小山丘；天底为银白色悬浮山体拼接的
区域，最高处突出剧情入口大门。两图沿用手绘风格，属于氛围插画而非精确关卡截图。
图片已保存到忽略目录 `local/assets/home-art` 并加入 Web 资源发布白名单；首页两种
终局配对展示这两张插画，DLL 0.4.9 也内嵌了 11 张封面用于录像便条。生成提示词见
`peak-nadir-art-prompts.json`。插画是否可见与地图入口是否有匹配资源分开判断。

完整录像便条中的斜切拼图仅纳入**实际录到**的区域，按经历顺序排列。
顶峰与终段共享地图层，因此仅凭数组索引、可用路线或结算最后一条 biome 不能补一张
“顶峰”图片。0.4.9 使用原生获胜事件区分顶峰撤离与天底分支，进入天底后排除顶峰。
普通区域根据实际采样分区生成摘要，不以完整地图路线冒充走过的路线。
旧录像缺乏证据时保持未确认，不虚构顶峰经历；旧完整录像不为封面解压全部数据。

足迹 Recorder 已正确把游戏分区转换为地图数组层；ReplayLab 的世界轨道则
保存原始 `Segment` 枚举，需要在回放时转换，不能改变旧录像 schema 的含义。
