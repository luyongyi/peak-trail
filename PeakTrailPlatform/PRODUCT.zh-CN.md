# PEAK Trail 产品定义

## 用户看到的产品

PEAK Trail 由两部分组成，但玩家只安装一个 Mod：

1. `PeakTrailRecorder.dll`：记录所有同步人类玩家的足迹、事件、体力和物品状态；同一 DLL 也负责为维护者采集当前已加载地图的 2.5D 数据。
2. 静态 GitHub Pages：自带已经验收并登记的地图包。普通访客只导入足迹文件，不需要另外提供地图文件。

独立的 `PeakMapExporter.dll` 只属于早期开发拆分，不是最终安装形态。

## 地图原则

- 当前游戏构建包含 `Level_0` 至 `Level_20` 共 21 张烘焙日常场景；每日接口的 `LevelIndex` 只选择一个槽位。
- 地图由用户自己的游戏运行时直接捕获为正射纹理与高度场，不经过 Blender 猜测或重新建模。
- 每个地图包绑定 `sceneName`、Steam `gameBuildId`、投影版本、坐标约定以及纹理/高度资源哈希。
- Pages 只从内嵌 catalog 加载与所选足迹完全匹配的地图。无法证明匹配时隐藏底图，不做近似猜测。
- 游戏更新后，新 build 必须重新验收受影响的地图包；旧 build 仍可用于回放旧足迹。

## 足迹库与时间线

- 一次可选择多局、多天的日志；以 `startedAtUtc` 转换到浏览器本地日期后分组。
- 先选择日期，再选择该日局次；每局独立保留场景、build、玩家和持续时间。
- 时间线可拖动或播放。地图只显示播放头之前的路线，并在当前时间显示每名玩家的位置与状态。
- 死亡、复活、昏迷、恢复、传送、加入、离开、分区推进、物品变化等事件可点击跳转。
- 旧版只有位置的日志继续可读；没有记录到的体力或物品显示为“无数据”，不伪造为零或空背包。

## 玩家遥测

目标字段以游戏中对各同步角色实际可观察的数据为准：

- 当前体力、最大体力、额外体力；
- 当前手持物品与可可靠读取的物品槽；
- 物品状态变化事件；
- 位置、朝向、死亡/昏迷状态和场景全局推进。

遥测变化本身可以触发记录，不能只在角色移动时采样。对于客户端无法权威观察的字段，协议会标记来源或缺失，而不是猜测。

## 隐私与发布

- 按需求保留真实稳定的平台 ID 与昵称，不生成随机参与者 ID。
- 日志只在本机写入、只在浏览器本地解析；不会由 Pages 上传到服务器。
- 稳定 ID、昵称、足迹和物品状态属于可识别的多人遥测，录制与分享前需要所有参与者同意。
- PEAK 派生地图资源在获得适当发布许可前保持本地；代码和空 catalog 可以先发布。
