# PeakTrailRecorder 0.8.5

Live appearance now includes the game's real ghost, petrification and blindness
states for both the local player and synchronized teammates.

- Ghosts require a native `PlayerGhost` instance associated with the exact
  recorded character. Position and rotation are sent separately from body
  samples, so the web viewer follows the ghost without adding its movement to
  living routes or heatmaps. Local first-person hiding does not erase its
  independently rendered web portrait or map marker.
- Petrification records the active native stone layer, trigger/progress and
  the actual shared-material `_Petrify` value. Blindness records the native
  Blind Card state. Inventory, death and ordinary status amounts are not
  substituted for these visual observations.
- Readiness and clear observations replace previous snapshots through the
  live relay, reconnect and replay. Reviving, losing the native entity or
  leaving cannot leave an old ghost or blindfold cached on the viewer.

The web uses the original ghost mesh and its owner's recorded face, a separate
original stone head renderer, and the original Blind Card. The stone coverage
and lighting are web approximations, rather than a reconstruction of Unity's
complete layered shader or character animation.

The reference target is installed Steam build 25739797. Update the single
`PeakTrailRecorder.dll` in `BepInEx/plugins/`, then restart PEAK. Existing live
sharing settings and the airport code workflow continue to apply.
