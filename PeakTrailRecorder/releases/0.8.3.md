# PeakTrailRecorder 0.8.3

Records native item use and confirmed final placement as two linked point events. The use
point is the actor's center; the spawn point is the native instantiated object or completed
placement RPC's position. Spawn `prefabName` is the generated object, including rope anchors
instead of the rope gun. The existing four-letter live code and viewer links are unchanged.

Initial coverage: climbing spikes via their actual pocket-slot hammer method, Constructable
placements, ShelfShroom/CloudFungus, hand-placed rope and the rope shooter's final anchor.
Photon instantiation and explicit placement/attachment RPCs are observed together. Repeated
callbacks for one native spawned object are deduplicated. No movement, rotation, collision
history, despawn tracking or inferred player attribution is added.

The independent route journal now exports optional top-level `itemEvents`. It remains active
when local full recording is off and live sharing is on. Same-frame events force one disk sync
and seal; compression, HTTP retries and crash recovery use the existing durable outbox. Unknown
actors remain unknown for the whole action; IDs are scoped to the recording. Previously sealed
event content stays stable. The archive retains at most 4,096 item events and logs when full.

Validation against installed PEAK build 25739797 includes current native signatures, Harmony
argument names, pocket-slot fields, the actual Photon instantiate call chain, final-anchor
source association, duplicate RPC handling, immutable unknown identities, optional old-journal
output and live anonymization. `ItemEventsContract` can emit a synthetic trajectory fixture.
