# PeakTrailRecorder 0.8.4

The airport now reserves a real four-letter live code. Copy it from the game's
**Settings → General → Live code** before the climb. Viewers can enter it immediately
and see a waiting page. Entering the map activates the same code and viewing link.
The main menu shows the setting and asks you to join the airport first.

One room publisher owns the reservation independently of local recording files. Teammates
share the airport reservation and its single lease; standby peers take over the same code
after a lease expires. No airport positions or fictitious run manifest are published.
The real RunId can arrive after loading; activation waits for it without changing codes.
Only a namespaced room hash is transmitted, never the raw Photon room name.

Live time begins when the playable run is configured, excluding airport waiting. Restarting
the optional local RecordingSession preserves the publisher, code and live clock. Closing
sharing, leaving the room or exiting immediately clears the code and releases the owned
lease asynchronously. Returning to the airport starts a new reservation. An old session
whose end request was lost is retired before a confirmed new airport stay reuses its alias.
Loading and late RunId are kept distinct from that airport evidence; owner-only run-key
verification prevents records from different runs being mixed.

The 0.8.3 native item events and independent durable route outbox are unchanged. No game
installation is modified by building the release.

Validation includes airport waiting/heartbeats with no records, same-code activation,
lost activation response retries, early-loading standby takeover, old-end loss recovery,
late RunId, independent recording clocks, required run-key verification, immediate disposal
and standby release. Current PEAK build 25739797 is the compilation/reference target.
